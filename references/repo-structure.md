# Repo Structure

Layout of a database repository generated by this skill. Create only the folders the confirmed tree lists; empty folders get a `.gitkeep`.

```
<repo>/
├── database/                     sources of truth (current schema)
│   ├── extensions.sql            CREATE EXTENSION … WITH SCHEMA extensions
│   ├── schemas.sql               schemas owned by the owner role; switches to that role
│   ├── checks.sql                project integrity checks (run last in bootstrap)
│   ├── security/
│   │   ├── roles.sql             group + login roles, database-level privileges
│   │   └── grants.sql            schema/table/function grants, default privileges
│   ├── functions/                one function per file
│   ├── models/                   one table per file (+ its indexes, RLS, policies, comments)
│   │   └── <schema>/             only when there are schemas besides public
│   ├── triggers/                 one file per trigger purpose
│   ├── seeds/                    reference data, one file per table; dev.sql = mock data
│   └── migrations/               MIG-NNN-<concept>-<YYYYMMDDHHmm>.sql
├── docs/
│   ├── flows/                    one markdown per business flow (kebab-case)
│   ├── adr/                      ADR-NNN-<decision>.md
│   └── audits/                   optional, written by the audit command
├── docker/db.Dockerfile          only if extensions outside the official image are used
├── .env / .env.example
├── .gitignore / .gitattributes
├── bootstrap.sql                 GENERATED — never edit by hand
├── build.ps1 | build.py | build.mjs   one of them, the user's choice
├── contributing.md
├── docker-compose.yml (+ docker-compose.dev.yml if the dev seed exists)
└── playground.sql                personal scratch file, always git-ignored
```

## Rules

- **One entity per file.** A table file contains the table, its indexes, `ENABLE/FORCE ROW LEVEL SECURITY`, its policies and its `COMMENT`s — everything needed to understand that table in one place.
- **Numeric prefixes define dependency order** for models, functions, triggers and seeds: `010-tenants.sql`, `020-users.sql`. Use steps of 10 so new files fit in between. The prefix is global across schema subfolders (the build sorts by file name first), so a table in `models/billing/` that references `models/auth/020-users.sql` gets a higher number.
- `000-schema-migrations.sql` is always the first model, in `public`.
- **Schema subfolders.** With only `public`, files sit directly in `models/`. As soon as the project has other schemas (`auth`, `billing`…), every model goes in a folder named after its schema, `public` included.
- **File header.** Every SQL file starts with two comment lines: `-- <file name>` and `-- <short purpose>`. The build `check` enforces it.
- **Names.** Files and folders in kebab-case; migrations and ADRs keep their uppercase prefix (`MIG-`, `ADR-`).
- `playground.sql` is never committed. `.env` is never committed; `.env.example` lists variable names with empty values.

## Mapping to the bootstrap order

| Bootstrap step | Source |
|---|---|
| 1. Extensions | `database/extensions.sql` |
| 2. Roles | `database/security/roles.sql` |
| 3. Schemas | `database/schemas.sql` |
| 4. Functions | `database/functions/**/*.sql` |
| 5. Models | `database/models/**/*.sql` |
| 6. Triggers | `database/triggers/**/*.sql` |
| 7. Grants | `database/security/*.sql` except `roles.sql` |
| 8. Reference seeds | `database/seeds/**/*.sql` except `dev.sql` |
| 9. Migration baseline | generated from `database/migrations/` file names |
| 10. Integrity checks | generated RLS check + `database/checks.sql` |

Roles come before schemas (a deliberate order): schemas are created with the owner role as their owner, so that role must exist first.
